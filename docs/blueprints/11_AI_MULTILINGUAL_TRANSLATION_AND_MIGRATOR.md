# 11. Многоезичен AI Конвейер и Пакетна Миграция (Batch Migrator)

## 1. Концепция и Бизнес Стойност
Поддръжката на многоезично съдържание (напр. 6 езика: `EN, ES, IT, FR, DE, BG`) обикновено страда от два тежки проблема:
1. **Огромна умора при въвеждане на данни**: Ако администратор или потребител трябва да попълва по 6 езикови полета за всяко заглавие, описание и стъпка, никой няма да създава съдържание.
2. **Добавяне на нов език на по-късен етап**: Когато проектът стартира с 2 езика и след 6 месеца се добавят още 4 езика, стотици съществуващи записи в базата остават без превод за новите езици.

Този модул решава и двата проблема чрез:
- **Едноезиков вход с автоматичен AI превод при запис**: Потребителят/администраторът пише **само на своя активен език**. При натискане на „Запази“, AI автоматично превежда съдържанието на каноничния базов език (`en`) и на всички останали поддържани езици (`translations.{lang}`).
- **Пакетна AI Миграция (`AIMultilingualMigrator`) с управление на квоти (HTTP 429)**: Административен инструмент, който сканира колекциите в базата, открива кои записи нямат пълен превод за даден език и ги превежда пакетно с **Dry Run преглед**, **автоматичен таймер за изчакване при Rate Limit (429)** и контрол за пауза/възобновяване.

## 2. Абстрактна Схема на Данните (Каноничен модел за многоезичен документ)

## 3. Ключова Логика, Гранични Случаи и Защити

### 3.1. Защита срещу вложени обекти при AI превод (`toSafeStr` Guard)
Понякога LLM моделите връщат обект `{"en": "Title", "bg": "Заглавие"}` вместо очаквания низ `"Title"`, когато превеждат в JSON режим. Ако този обект се подаде директно в JSX, React хвърля фатална грешка `Objects are not valid as a React child`.
- **Задължителна нормализация преди запис в базата**:
  ```javascript
  export function toSafeStr(val, preferredLang = 'en', fallback = '') {
    if (val === null || val === undefined) return fallback;
    if (typeof val === 'string') return val.trim();
    if (typeof val === 'number' || typeof val === 'boolean') return String(val);
    if (typeof val === 'object' && !Array.isArray(val)) {
      if (typeof val[preferredLang] === 'string') return val[preferredLang].trim();
      if (typeof val.en === 'string') return val.en.trim();
      const firstStr = Object.values(val).find(v => typeof v === 'string');
      if (firstStr) return firstStr.trim();
    }
    return fallback;
  }
  ```

### 3.2. Интелигентна проверка за пълнота на превода (`hasCompleteTranslation`)
Пакетният мигратор не проверява просто дали съществува ключ `doc.translations?.es`, а проверява **всички задължителни полета и дължините на масивите**:
- Ако базовата рецепта има 5 стъпки (`doc.steps.length === 5`), но `doc.translations.es.steps` има само 3 стъпки или липсва описание, записът се маркира като **непълен (`needsTranslation = true`)**.

### 3.3. Парсване на HTTP 429 Rate Limit и автоматичен Cooldown (`parseRetryDelaySeconds`)
Безплатният и стандартният план на Gemini API имат лимити за заявки в минута (RPM). Когато пакетният мигратор обработва 50 документа подред и получи HTTP 429 (`RESOURCE_EXHAUSTED`), той **не прекъсва миграцията с грешка**, а:
1. Извлича точното време за изчакване от съобщението на Google (`Please retry in 42.5s` или `retryDelay: "42s"`), добавя буфер от `+3 секунди` (по подразбиране `65s`, ако няма изрично число).
2. Стартира визуален обратен брояч в UI („Лимит на API квотата — автоматично продължаване след 45 сек...“).
3. След изтичане на таймера автоматично повтаря същия документ и продължава напред.

```javascript
export function parseRetryDelaySeconds(errorMessage, defaultSec = 65) {
  if (!errorMessage) return defaultSec;
  const match = errorMessage.match(/retry in\s+([\d.]+)\s*s/i) ||
                errorMessage.match(/retryDelay["']?\s*:\s*["']?(\d+)s/i);
  if (match && match[1]) {
    return Math.ceil(parseFloat(match[1])) + 3;
  }
  return defaultSec;
}
```

### 3.4. Запазване на HTML структура при превод на страници
Когато се превежда богато форматирано съдържание (напр. секция „Правила за реклама“ или блог статия), системният промпт инструктира AI да запази **всички HTML тагове, класове (`class="..."`) и атрибути непокътнати**, превеждайки единствено видимия текст между таговете.

## 4. UI/UX Архитектура и Потребителски Потоци

### 4.1. Едноезикова форма с автоматичен превод (Single-Language Input Modal)
- Когато потребителят е на испански (`es`), модалът за създаване/редактиране показва полетата на испански.
- При запис бутонът преминава в състояние *„Записване и AI превод (EN, IT, FR, DE, BG)...“*, извиква единична пакетна заявка към LLM и записва готовия многоезичен документ във Firestore.

### 4.2. Табло за пакетна миграция (`AIMultilingualMigrator`)
Разположено в Административния панел, таблото предлага:
1. **Таблица за покритие по колекции и езици**: Показва за всяка колекция (`recipes`, `chefs`, `events`) колко документа са напълно преведени на всеки от 6-те езика (напр. `ES: 42 / 110 (38%)`) с цветна прогрес лента.
2. **Dry Run режим (Симулация)**: Позволява стартиране на превода само за 1–3 записа и преглед на генерирания JSON резултат на екрана **без запис във Firestore**.
3. **Пълен контрол на процеса**: Бутони за **Старт**, **Пауза / Продължи**, **Отказ**, настройка на паузата между заявките (напр. `4000 ms` за безплатен API ключ) и жива конзола с логове за всеки преведен документ.

   - Във формите за създаване и редакция показвай полетата само на текущия активен език на потребителя.
   - При запис (ако е наличен AI ключ) извиквай единна функция `translateEntityToAllLanguages`, която с 1 LLM заявка връща английската базова версия + обекта `translations` за всички останали поддържани езици.
3. **Пакетна миграция (`AIMultilingualMigrator.jsx` + `aiTranslationMigrator.js`)**:
   - Сканирай избраните Firestore колекции и изчислявай процентно покритие за всеки език (проверявай и дължината на масивите като `steps`).
   - Имплементирай `Dry Run` режим (преглед без запис в базата), бутони за Пауза/Продължаване/Стоп и регулируемо забавяне между заявките.
   - При грешка HTTP 429 (Rate Limit / Resource Exhausted) парсвай времето за изчакване (`retry in Xs`), показвай жив обратен брояч в интерфейса и автоматично подновявай превода на същия документ след изтичане на таймера.
